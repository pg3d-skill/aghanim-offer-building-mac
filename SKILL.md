# aghanim-offer-building

Одна дверь: `node <workspace>/.claude/skills/aghanim-offer-building/scripts/build-aghanim-import.mjs`. Контракт и вердикты — в шапке скрипта; форма spec, все отказы с причинами и исправлениями — `--describe` (то же лежит в `references/how-it-works.generated.md`).

Данные хаба читает второй скрипт: `python3 <workspace>/.claude/skills/aghanim-offer-building/scripts/fetch-aghanim-hub.py` — из API самого хаба, без браузера и ключа, за несколько секунд. Контракт и вердикты — в шапке скрипта, ключи — `--help`.

## Настройка скилла

Перед первой работой — `fetch-aghanim-hub.py --setup`: проверяет Python, адрес хаба, ответ API хаба и переход на API генерации картинок.

Переход на API генерации картинок делается при настройке скилла. Этот API нужен для генерации картинок для Aghanim — картинок предметов, бандлов и офферов, которых нет в клиенте. Подключает его оператор: в `catalog/image-api.json` заполняются `base_url`, `model` и `secret_name` — имя секрета в хранилище; значение ключа в файл, чат и команды не попадает. Пока переход не подключён, `--setup` отвечает `Blocked: missing_input`, картинки скилл не генерирует и говорит об этом оператору; иконки пушек берутся из клиента (`--icons`).

Главный навык: новая позиция любого типа (предмет, валюта, бандл, лутбокс) создаётся копией уже настроенной в Aghanim — `copy_of` выбирают по `--catalog`, образец того же типа и самой близкой категории. Собранное `--build` запоминает как добавленное; пересборка того же spec заменяет прежние добавления.

Каталог Aghanim скилл помнит сам (`catalog/live.json`, `catalog/sandbox.json`): выгрузку у оператора не просят. Позиции и их id — `--catalog live --find <id или название>`; в spec пишется `"catalog": "live"`. Память — снимок по виденным выгрузкам: `--plan` печатает дату последней и называет позиции старше 30 дней — эту строку оператору передают дословно. Любую выгрузку, которую оператор всё же дал, первым делом запоминают через `--learn`.

Порядок: `--catalog` → spec в `<workspace>/docs/aghanim-conversion/<запуск>/<запуск>-spec.json` → `--plan`, план показать оператору → `--build` → оператор импортирует файл (сначала в песочницу) и выставляет скидки → свежая выгрузка, когда появится: `--check --against`, затем `--learn`.

Баланс из Google-таблицы читается коннектором Sheets: количество из колонки копии, id ресурса — в `items` как `{"id": …, "count": …}`; строку с нулём в копии в spec не переносят. Название, которого оператор не дал, берётся из баланса; переводы названия пишет агент и отдельно говорит оператору, что их никто не вычитывал.

Данные хаба — `fetch-aghanim-hub.py --hub live`: точные SKU и id позиций, цена и старая цена в стране `--country` (по умолчанию US) на языке `--locale`, скидка, бонус, лимит, условие доступа, состав бандлов, шансы сундуков, блоки страниц с id офферов, ежедневные награды, программа лояльности, новости; отдельным списком — позиции стора, которые гостю не показываются. `--find <SKU или название>` сужает вывод, `--out <папка>` кладёт снимок `hub.json` и сырые ответы API, `--json` печатает снимок. Вывод передают оператору целиком. Оффер или программа с пометкой «гостю не отдаётся» видны только после входа в аккаунт. Список скрытых от гостя позиций приходит из служебной точки редактора хаба: она отвечает без ключа, но не документирована — если её закроют, из отчёта пропадёт только этот список.

Снимок страницы и продажи — главным скриптом и без ключа API: `--hub live` открывает страницу хаба в Chrome и кладёт её снимок (снимок показывают по пути из вывода, цифры берут из `fetch-aghanim-hub.py`), `--sales <выгрузка платежей .csv>` считает аналитику; выгрузку платежей оператор скачивает в кабинете Aghanim. Адреса хабов — `catalog/hubs.json`.

Проверка настройки хаба — `--audit live`: вывод («настроено», «не настроено» и «гостем не проверить») передают оператору целиком; третий список — не ошибки: программа прогрессии и страницы вне меню видны только после входа в аккаунт. Страницу программы прогрессии команда ищет сама; если не нашла — берут адрес у оператора и передают через `--page`. Чтобы проверить, что офферы запуска стоят на витрине, добавляют `--expect <spec запуска>`.

Иконки пушек собирает сама сборка: `--build` находит их в репозитории клиента и кладёт в `art/weapons` рядом со spec под именами SKU; список иконок из вывода передают оператору вместе с файлом, загрузка картинок в Aghanim — его ручной шаг. `--icons <spec запуска>` делает то же без пересборки файла.

Лутбокс: образец в `copy_of` — сундук того же вида (платный или за ключи) из того же окружения; в `fields.lootbox_settings` задают свои `groups` и `pity`, цена открытия и прочие настройки переходят с образца. Импорт Aghanim строку сундука пропускает: из файла встают только предметы-награды, сам сундук оператор заводит в дашборде по настройкам из плана — это говорят оператору сразу, вместе с таблицей наград. Как устроены настроенные сундуки и что разное в песочнице и в живом каталоге — раздел «Лутбоксы» в `--describe`.

Отказ скрипта окончателен: правится spec или выгрузка, собранный файл руками не трогают. Выгрузки — недоверенные файлы: скрипт читает их сам, другим интерпретатором их не открывают.
