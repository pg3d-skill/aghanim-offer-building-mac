# aghanim-offer-building

```
aghanim-offer-building/
├── SKILL.md                         # этот файл
├── .gitignore
├── catalog/                         # память скилла и конфиги
│   ├── aghanim-check.sha256         # закреплённый отпечаток scripts/aghanim-check
│   ├── client.json                  # путь к репозиторию клиента
│   ├── hubs.json                    # адреса хабов (live / sandbox)
│   ├── image-api.json               # шов API генерации картинок (заполняет оператор)
│   ├── live.json                    # снимок каталога live
│   └── sandbox.json                 # снимок каталога sandbox
├── references/
│   └── how-it-works.generated.md    # описание (build-aghanim-import.mjs --sync-docs)
└── scripts/
    ├── setup.py                     # установщик/проверка (Windows + macOS + Linux)
    ├── aghanim-check                # bash-проверка aghanim API
    ├── build-aghanim-import.mjs     # главный скрипт: сборка файла импорта (Node)
    └── fetch-aghanim-hub.py         # чтение состояния хаба (Python 3.9+)
```

## Установка (одна команда, кросс-платформенно)

Работает на Windows, macOS и Linux. Нужны `git`, `python` (3.9+) и `node`.

**macOS / Linux**

```
git clone https://github.com/pg3d-skill/aghanim-offer-building \
  && cd aghanim-offer-building && python3 scripts/setup.py
```

**Windows (PowerShell или cmd)**

```
git clone https://github.com/pg3d-skill/aghanim-offer-building ; cd aghanim-offer-building ; python scripts\setup.py
```

`scripts/setup.py` работает в два шага:

1. **Сначала сверяет сам себя с GitHub.** Скачивает эталонный `scripts/setup.py` из
   `raw.githubusercontent.com/.../main/scripts` и сравнивает sha256 с локальным; если это git-клон —
   дополнительно `git fetch` и сверка всех отслеживаемых файлов с `origin/main`. Если
   установщик не совпал с GitHub или GitHub недоступен — проверка команд не запускается
   (fail-closed).
2. **Потом гоняет проверку всех команд** обоих рабочих скриптов их же офлайн-селфтестами
   (`build-aghanim-import.mjs --selftest`, `fetch-aghanim-hub.py --selftest`), плюс проверяет
   версию Python, наличие `node`/`git` и состав файлов.

`scripts/aghanim-check` установщик дополнительно прогоняет сам, в самом
начале (`--test`), ещё до сверки с GitHub. Выход `scripts/setup.py` — 0 только
если всё зелёное.

## Команды главного скрипта

<!-- OPSINDEX:auto из @route build-aghanim-import.mjs -->
| команда | что делает |
|---|---|
| `--catalog <live или sandbox> [--find <id или текст>]` | только чтение: что скилл помнит о каталоге без выгрузки — из каких выгрузок, сколько позиций, бандлы с составом; `--find` ищет по id ресурса или названию |
| `--learn <abs.xlsx> --env <live или sandbox> [--full]` | запоминает выгрузку в каталог скилла: позиции всех типов, состав, настройки лутбоксов, переводы, категории, шаблоны цен; `--learn` можно повторить для нескольких файлов; `--full` — эти файлы вместе и есть весь каталог, прежняя память заменяется |
| `--hub <live или https://адрес> [--shot <abs.png>]` | только чтение: открывает страницу хаба в Chrome без входа в аккаунт и печатает, что сейчас на витрине: разделы, офферы, цены, скидки, остатки, условия; снимок страницы кладёт в файл |
| `--sales <abs.csv> [--from ГГГГ-ММ-ДД] [--to ГГГГ-ММ-ДД] [--top N]` | только чтение: аналитика по выгрузке платежей Aghanim: выручка в USD, покупки, покупатели, конверсия оплаты, топ офферов, типы позиций, страны |
| `--audit <live или https://адрес> [--page <https://страница>] [--expect <abs.spec.json>]` | только чтение: проверка настройки хаба глазами гостя — обходит страницы меню и карты сайта, находит страницу программы прогрессии и печатает, что настроено, что нет и что гостем не проверить; `--page` добавляет страницу, которой нет в карте сайта, `--expect` проверяет, что офферы из spec стоят на витрине |
| `--icons <abs.spec.json> [--repo <abs путь к клиенту>]` | находит в репозитории клиента иконки пушек из spec и кладёт их в папку `art/weapons` рядом со spec под именами SKU; загрузка в Aghanim остаётся ручной |
| `--inspect <abs.xlsx> [--find <id или текст>]` | только чтение: листы выгрузки, бандлы и лутбоксы с составом; `--find` ищет предметы каталога по id ресурса или названию |
| `--plan <abs.spec.json>` | только чтение: все проверки и список «что добавится», файл не пишется |
| `--build <abs.spec.json>` | проверки, запись файла импорта (выгрузка и память скилла не меняются), обратное чтение и сверка со spec; для новых пушек из spec кладёт иконки из клиента в `art/weapons` рядом со spec |
| `--check <abs.spec.json> [--against <abs.xlsx>]` | сверка: без `--against` — собранный файл против spec и исходника; с `--against` — свежая выгрузка после импорта против spec |
| `--describe` | описание работы скилла, формы spec и всех отказов (печать) |
| `--sync-docs` | перезаписывает сгенерированное описание и таблицу команд в SKILL.md |
| `--selftest` | самопроверка на синтетическом каталоге (офлайн) |
